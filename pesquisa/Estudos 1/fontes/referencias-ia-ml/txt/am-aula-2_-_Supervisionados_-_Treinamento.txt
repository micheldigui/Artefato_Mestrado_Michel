➔ Conjunto de Validação com "Validação Cruzada" - Cross Validation
◆ Na validação cruzada, normalmente não é definido previamente um percentual fixo (como
10%, 15% ou 20%) para validação. O conjunto de dados é dividido em K subconjuntos
(folds) de tamanho aproximadamente igual
◆ O processo realiza k iterações, onde:
● em cada iteração, K-1 subconjuntos são utilizados para treinamento;
● o subconjunto restante é utilizado para validação;
● o desempenho do modelo é avaliado e armazenado.
Entendendo e Preparando Dados com Scikit Learn
➔ Conjunto de Validação com "Validação Cruzada" - Cross Validation
◆ Ao final das K iterações, calcula-se a média das métricas obtidas (por exemplo, acurácia,
precisão, RMSE, R²), fornecendo uma estimativa mais robusta da capacidade de
generalização do modelo
◆ Quando utilizada em conjunto com técnicas de ajuste de hiperparâmetros (como Grid
Search ou Random Search), a validação cruzada permite comparar diferentes
configurações do modelo e selecionar aquela que apresenta melhor desempenho médio

Precision
➔ A Precision (precisão) em um problema de classificação mede a proporção
das previsões positivas de uma determinada classe que realmente estavam
corretas
➔ Quando o modelo diz que uma amostra pertence a uma classe, com que
frequência ele está certo?
➔ Preciosion para a Classe Setosa → 7 / (7 + 3) = 70,00%
Macro Precision
➔ Calcula a Precision de cada classe e faz a média simples
➔ É útil quando você quer avaliar se o modelo trata bem todas as classes,
inclusive classes raras
➔ Neste caso, todas as classes têm a mesma importância
Weighted Precision
➔ Faz a média ponderada pelo número de exemplos de cada classe
➔ Representa melhor o desempenho global quando existe desbalanceamento
de classes
➔ Serão atribuídos pesos para as classes, que podem indicar quais classes são
mais importantes
Micro Precision
➔ Agrupa todos os verdadeiros positivos e falsos positivos
◆ Considera o desempenho geral do modelo
➔ Considerando todas as previsões juntas, qual percentual das previsões
positivas estava correto?
A importância do Precision
➔ A Medida Precision (precisão) é importante quando:
◆ Falsos positivos são caros
● Detecção de fraude
● Diagnóstico médico
● Detecção de conteúdo impróprio
◆ Se deseja ter confiança nas previsões
● Um modelo que recomenda medicamentos
Recall
➔ O Recall (também chamado de sensibilidade, taxa de verdadeiros positivos ou True
Positive Rate - TPR) mede a capacidade do modelo de encontrar corretamente os
exemplos de uma determinada classe que realmente existem
➔ Dentre todos os exemplos que realmente pertencem a uma classe, quantos o modelo
conseguiu identificar corretamente?
➔ Recall para a Classe Setosa → 7 / (7 + 8) = 46,66%
Recall por Classe
➔ É o Recall calculado individualmente para cada classe
➔ Neste exemplo teremos:
◆ Recall para a Classe Setosa → 7 / (7 + 8) = 46,66%
◆ Recall para a Classe Virgínica → 8 / (8 + 1 + 9) = 44,44%
◆ Recall para a Classe Versicolor → 6 / (6 + 4 + 2) = 50,00%
Recall Macro
➔ Calcula o Recall por cada classe e depois tira a média aritmética deles
◆ Para o exemplo em questão sería (46.66 + 44.44 + 50.00) / 3 = 47.03%
➔ Em média, considerando que todas as classes têm a mesma importância, qual
percentual dos exemplos de cada classe o modelo consegue encontrar?
◆ É importante quando:
● Todas as classes possuem a mesma relevância
● Não desejamos que uma classe dominante esconda o desempenho ruim de outra
● Existe desbalanceamento de classes
Recall Macro
➔ Exemplo:
◆ Classe (Doença Rara): 50 amostras
◆ Classe (Pessoas Saudáveis): 50.000 amostras
Mesmo sendo rara, a doença pode ser muito importante.O Recall Macro garante que a
classe rara tenha o mesmo peso

Como utilizado o Recall
➔ O Recall é uma das métricas mais importantes na avaliação de modelos de
aprendizado de máquina porque mede a capacidade do modelo de identificar
corretamente os exemplos que realmente pertencem a uma determinada
classe
➔ Um modelo pode apresentar uma elevada acurácia e, ainda assim, possuir
um Recall muito baixo para uma determinada classe
➔ Um Recall elevado indica que:
◆ o modelo consegue identificar a maioria dos exemplos pertencentes à classe
◆ existem poucos falsos negativos
◆ dificilmente um exemplo positivo deixa de ser identificado
Como utilizado o Recall
➔ Um Recall baixo indica que:
◆ muitos exemplos da classe estão sendo perdidos
◆ existe uma quantidade elevada de falsos negativos
◆ o modelo apresenta dificuldade para reconhecer essa classe
Nesse caso, mesmo que as previsões realizadas sejam corretas, muitos
exemplos positivos deixam de ser detectados
Em quais situações o Recall é importante?
➔ Quando deixar de identificar um exemplo positivo pode causar
consequências graves
◆ diagnósticos médicos
◆ detecção de situação de perigo/emergência
◆ detecção de fraudes e delitos

Precision x Recall
➔ Embora frequentemente analisados em conjunto, Recall e Precision medem
aspectos diferentes
Recall avalia a capacidade do modelo de encontrar todos os exemplos positivos
Precision avalia a confiabilidade das previsões positivas realizadas pelo modelo
➔ Um modelo pode apresentar:
◆ Recall alto e Precision baixa: identifica quase todos os exemplos positivos, mas gera muitos falsos
positivos
◆ Precision alta e Recall baixa: realiza poucas previsões positivas, porém com alta confiabilidade,
deixando muitos exemplos positivos sem identificação
Especificidade
➔ Enquanto o Recall (Sensibilidade) mede a capacidade do modelo de
identificar corretamente os exemplos positivos, a Especificidade mede a
capacidade do modelo de identificar corretamente os exemplos negativos
➔ De todos os exemplos que realmente não pertencem à classe analisada,
quantos o modelo conseguiu identificar corretamente como negativos?
➔ Tomando como exemplo um caso de um classificador para identificar
pessoas com uma certa doença
◆ A Especificidade mede a capacidade do modelo de identificar corretamente os indivíduos
que não possuem a doença. Em termos percentuais, ela indica que, dentre todas as
pessoas realmente saudáveis, o modelo classificou corretamente X% como não portadoras
da doença.
Especificidade
➔ Para o exemplo de classificação de iris Setosa no Dataset íris:
Especificidade → 27 / (27 + 3) = 90,00%
➔ Das flores que não eram Setosa, o modelo classificou corretamente
aproximadamente 90% como "não Setosa"
➔ A Especificidade é particularmente importante quando um falso positivo
possui um custo elevado. Enquanto o Recall busca reduzir falsos negativos,
a Especificidade busca reduzir falsos positivos. Dependendo da aplicação,
um falso positivo pode gerar custos significativos
Especificidade
➔ Uma Especificidade elevada indica que:
◆ o modelo produz poucos falsos positivos
◆ dificilmente classifica exemplos negativos como positivos
◆ possui boa capacidade de rejeitar exemplos que não pertencem à classe
➔ Uma Especificidade baixa indica que:
◆ muitos exemplos negativos estão sendo classificados como positivos

Especificidade
➔ Em problemas multiclasse, a Especificidade é calculada para cada classe
individualmente, utilizando a estratégia One-vs-Rest (Um contra Todos)
◆ O que significa "One-vs-Rest"?
◆ Setosa × Não Setosa ou seja:
● Setosa → Positivo | Não Setosa → Negativo
Depois repete para as demais classes
➔ Entre todas as amostras que NÃO pertencem a esta classe, quantas o
modelo conseguiu identificar corretamente como NÃO pertencentes a ela?
Acurácia
➔ Mede a proporção de previsões que o modelo classificou corretamente em
relação ao total de previsões realizadas
➔ Uma acurácia de 95% significa que a cada 100 previsões o modelo classifica
corretamente 95 vezes
➔ Para a Classe de Iris Setosa
◆ Acurácia → (7 + 27) / (7 + 27 + 3 + 8) = 75,55%
Quando utilizar a Acurácia
➔ As classes são equilibradas
➔ Os custos dos erros são semelhantes
◆ errar uma classe tem aproximadamente o mesmo impacto que errar outra
➔ Avaliação inicial de modelos
◆ Quando estamos comparando os modelos (knn, SVM, Random Forest, etc.)
➔ A principal limitação da acurácia aparece quando existe
desbalanceamento de classes

F1-Score
➔ Combina a Precision e o Recall em uma única medida. Ele é especialmente
útil quando não basta saber apenas quantos exemplos o modelo encontrou
(Recall) ou quão confiáveis são suas previsões positivas (Precision)
➔ Imagine dois modelos para identificar a classe Setosa.
◆ Modelo A
● Precision = 95%
● Recall = 40%
● O modelo quase nunca erra quando diz que uma flor é Setosa, mas deixa escapar
muitas Setosas
◆ Modelo B
● Precision = 55%
● Recall = 98%
● O modelo encontra praticamente todas as Setosas, mas classifica muitas flores
de outras espécies como Setosa
F1-Score
➔ Qual modelo é melhor?
◆ Apenas olhando Precision ou Recall, não é possível responder
➔ F1-Score para a classe Setosa
◆ F1 → 2 x [ (70.00 x 46.66) / (70.00 + 46.66) ] = 55.99%
➔ Setosa
◆ Recall → 70.00
◆ Precision → 46.66
◆ F1 → 55.99 (um valor entre o Recall e Precision, equilibrando a avaliação)
Tipos de F1-Score
➔ Por Classe
◆ Calcula-se um F1 para cada classe
◆ É o mais informativo e mostra exatamente quais classes estão sendo bem classificadas
◆
É o apresentado pelo Scikit-Learn na classification_report

◆ Calcula a média simples dos F1 individuais

● Todas as classes possuem a mesma importância
● Avaliação justa de classes raras

◆ Classes desbalanceadas

➔ O F1-Score é uma métrica de equilíbrio entre Precision e Recall
◆ Útil quando se deseja um modelo que seja ao mesmo tempo preciso (poucos falsos positivos)
